# teleloom v0.6.0

This release adds a browser workspace for the local owner and improves native
client setup.

- Run `teleloom ui` to inspect the owner, profiles, exposed tools, jobs, receipts,
  and frozen reading evidence. A [private SSH tunnel](../gui-ssh.md) can forward
  this panel from a remote owner.
- Run `teleloom control` on the owner's machine to manage profiles, read
  policies, tool exposure, clients, proxies, and optional engines. The process
  must remain running while the management page is in use.
- Single-message sends show the exact recipient and text before confirmation.
  A recorded unknown outcome remains available for reconciliation.
- OpenCode 2 and Hermes can register the local server through their native CLI.
  Equivalent Windows paths match in the CLI and browser.

See the [installation guide](../getting-started.md), [Russian guide](../install-ru.md),
and [client setup](../clients.md). Upgrade the existing owner in place and
reconnect MCP clients to refresh discovery. The wheel, source archive and
`SHA256SUMS` identify the published artifact. Run `teleloom doctor` to compare
its version, build ID and source commit.

Automated checks use isolated owner state and substitute Telegram and provider
calls. Live browser account onboarding and live VPS acceptance are separate checks.
